# 开发示例手册

这份文档按“能直接照着用”的方式整理项目常用开发场景。它更像 Element Plus、x-file-storage 那类官网文档：先说明适用场景，再给完整示例，最后补注意事项。

## 1. 第一个业务接口

### 1.1 适用场景

新增普通业务模块，例如商品、文章、合同、客户、点位等。

推荐接口风格：

- 分页列表返回 `TableDataInfo`
- 详情返回 `Response<VO>`
- 新增、修改、删除返回 `Response<Void>`
- Service 新增、修改、删除默认返回 `int`

### 1.2 Controller 示例

```java
package com.ruoyi.system.controller;

import java.util.List;
import jakarta.annotation.Resource;
import jakarta.validation.Valid;
import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.validation.annotation.Validated;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import com.ruoyi.common.annotation.Log;
import com.ruoyi.common.core.controller.BaseController;
import com.ruoyi.common.core.domain.Response;
import com.ruoyi.common.core.page.TableDataInfo;
import com.ruoyi.common.enums.BusinessType;
import com.ruoyi.system.dto.ProductEditDto;
import com.ruoyi.system.dto.ProductQueryDto;
import com.ruoyi.system.dto.ProductSaveDto;
import com.ruoyi.system.service.IProductService;
import com.ruoyi.system.vo.ProductVo;

@Validated
@RestController
@RequestMapping("/system/product")
public class ProductController extends BaseController {

    @Resource
    private IProductService productService;

    @PreAuthorize("@ss.hasPermi('system:product:list')")
    @GetMapping("/list")
    public TableDataInfo list(ProductQueryDto queryDto) {
        startPage();
        List<ProductVo> list = productService.selectProductList(queryDto);
        return getDataTable(list);
    }

    @PreAuthorize("@ss.hasPermi('system:product:query')")
    @GetMapping("/{productId}")
    public Response<ProductVo> getInfo(@PathVariable Long productId) {
        return Response.success(productService.selectProductById(productId));
    }

    @PreAuthorize("@ss.hasPermi('system:product:add')")
    @Log(title = "商品管理", businessType = BusinessType.INSERT, bizType = "product")
    @PostMapping
    public Response<Void> add(@Valid @RequestBody ProductSaveDto saveDto) {
        return Response.toResponse(productService.insertProduct(saveDto));
    }

    @PreAuthorize("@ss.hasPermi('system:product:edit')")
    @Log(title = "商品管理", businessType = BusinessType.UPDATE, bizType = "product", bizId = "#editDto.productId")
    @PutMapping
    public Response<Void> edit(@Valid @RequestBody ProductEditDto editDto) {
        return Response.toResponse(productService.updateProduct(editDto));
    }

    @PreAuthorize("@ss.hasPermi('system:product:remove')")
    @Log(title = "商品管理", businessType = BusinessType.DELETE, bizType = "product", bizId = "#productIds")
    @DeleteMapping("/{productIds}")
    public Response<Void> remove(@PathVariable Long[] productIds) {
        return Response.toResponse(productService.deleteProductByIds(productIds));
    }
}
```

### 1.3 为什么 Controller 仍然继承 BaseController

列表接口需要 `startPage()` 和 `getDataTable(list)`，所以常规业务 Controller 仍建议继承 `BaseController`。

如果某个 Controller 完全没有分页、没有若依工具方法，也可以不继承。

| 场景 | 推荐写法 | 不推荐 |
| --- | --- | --- |

### 3.3 前端使用

```vue
<template>
  <el-table v-loading="loading" :data="productList">
    <el-table-column label="商品名称" align="center" prop="productName" />
    <el-table-column label="状态" align="center" prop="status" />
  </el-table>

  <pagination
    v-show="total > 0"
    :total="total"
    v-model:page="queryParams.pageNum"
    v-model:limit="queryParams.pageSize"
    @pagination="getList"
  />
</template>

<script setup>
import { listProduct } from '@/api/system/product'

const loading = ref(false)
const total = ref(0)
const productList = ref([])
const queryParams = reactive({
  pageNum: 1,
  pageSize: 10,
  productName: undefined
})

function getList() {
  loading.value = true
  listProduct(queryParams).then(response => {
    productList.value = response.rows
    total.value = response.total
  }).finally(() => {
    loading.value = false
  })
}

getList()
</script>
```

### 3.4 请求参数说明

若依分页默认从请求参数读取：

| 参数 | 含义 | 示例 |
| --- | --- | --- |
| `pageNum` | 当前页 | `1` |
| `pageSize` | 每页条数 | `10` |
| `orderByColumn` | 排序字段 | `createTime` |
| `isAsc` | 排序方向 | `desc` |
| `reasonable` | 分页合理化 | `true` |

业务查询参数继续放在 QueryDTO 中。

## 5. MapStruct 转换

### 5.1 Convert 接口

```java
package com.ruoyi.system.convert;

import java.util.List;
import org.mapstruct.Mapper;
import org.mapstruct.MappingTarget;
import com.ruoyi.system.domain.Product;
import com.ruoyi.system.dto.ProductEditDto;
import com.ruoyi.system.dto.ProductSaveDto;
import com.ruoyi.system.vo.ProductVo;

@Mapper(componentModel = "spring")
public interface ProductConvert {

    Product toEntity(ProductSaveDto saveDto);

    Product toEntity(ProductEditDto editDto);

    ProductVo toVo(Product product);

    List<ProductVo> toVoList(List<Product> list);

    void updateEntity(ProductEditDto editDto, @MappingTarget Product product);
}
```

### 5.2 Service 中使用

```java
@Service
public class ProductServiceImpl implements IProductService {

    @Resource
    private ProductMapper productMapper;

    @Resource
    private ProductConvert productConvert;

    @Override
    public int insertProduct(ProductSaveDto saveDto) {
        Product product = productConvert.toEntity(saveDto);
        product.setCreateTime(DateUtils.getNowDate());
        product.setCreateBy(SecurityUtils.getUsername());
        return productMapper.insertProduct(product);
    }

    @Override
    public int updateProduct(ProductEditDto editDto) {
        Product product = productConvert.toEntity(editDto);
        product.setUpdateTime(DateUtils.getNowDate());
        product.setUpdateBy(SecurityUtils.getUsername());
        return productMapper.updateProduct(product);
    }
}
```

### 5.3 查询后转 VO

```java
@Override
public ProductVo selectProductById(Long productId) {
    Product product = productMapper.selectProductById(productId);
    if (product == null) {
        throw new BizException("商品不存在");
    }
    return productConvert.toVo(product);
}
```

### 5.4 局部更新示例

如果以后做 PATCH 风格接口，可以先查旧数据，再把非空字段更新进去：

```java
@Override
public int patchProduct(ProductEditDto editDto) {
    Product product = productMapper.selectProductById(editDto.getProductId());
    if (product == null) {
        throw new BizException("商品不存在");
    }
    productConvert.updateEntity(editDto, product);
    product.setUpdateTime(DateUtils.getNowDate());
    product.setUpdateBy(SecurityUtils.getUsername());
    return productMapper.updateProduct(product);
}
```

注意：普通编辑接口默认按全量编辑处理，不建议把 PATCH 逻辑混进去。

```java
public List<ProductVo> selectProductList(ProductQueryDto queryDto) {
```

### 8.7 value-type 说明

```vue
<file-upload value-type="fileId" />
```

不加 `:`，表示传入字符串 `fileId`。

```vue
<file-upload :limit="5" />
```

加 `:`，表示传入 JavaScript 数字 `5`。

```vue
<file-upload :file-type="['pdf', 'docx']" />
```

加 `:`，表示传入数组。如果写成 `file-type="['pdf', 'docx']"`，组件拿到的是字符串，不是数组。

## 9. 文件生命周期绑定

### 9.1 新增业务数据

```java
@Override
@Transactional(rollbackFor = Exception.class)
public int insertProduct(ProductSaveDto saveDto) {
    Product product = productConvert.toEntity(saveDto);
    product.setCreateBy(SecurityUtils.getUsername());
    product.setCreateTime(DateUtils.getNowDate());
    int rows = productMapper.insertProduct(product);

    if (rows > 0) {
        businessStorageFileService.bindStorageFiles(
            product,
            String.valueOf(product.getProductId()),
            PRODUCT_STORAGE_FILE_FIELDS,
            businessStorageFileService.getOperator(product)
        );
    }
    return rows;
}
```

### 9.2 修改业务数据

```java
@Override
@Transactional(rollbackFor = Exception.class)
public int updateProduct(ProductEditDto editDto) {
    Product oldProduct = productMapper.selectProductById(editDto.getProductId());
    if (oldProduct == null) {
        throw new BizException("商品不存在");
    }

    Product product = productConvert.toEntity(editDto);
    product.setUpdateBy(SecurityUtils.getUsername());
    product.setUpdateTime(DateUtils.getNowDate());
    int rows = productMapper.updateProduct(product);

    if (rows > 0) {
        businessStorageFileService.syncStorageFiles(
            product,
            oldProduct,
            String.valueOf(product.getProductId()),
            PRODUCT_STORAGE_FILE_FIELDS,
            businessStorageFileService.getOperator(product)
        );
    }
    return rows;
}
```

实际方法名以项目内 `IBusinessStorageFileService` 为准。生成器生成的文件生命周期代码优先于手写示例。

### 9.3 删除业务数据

```java
@Override
@Transactional(rollbackFor = Exception.class)
public int deleteProductByIds(Long[] productIds) {
    int rows = productMapper.deleteProductByIds(productIds);

    if (rows > 0) {
        businessStorageFileService.markStorageFilesWaitDeleteByBiz(
            productIds,
            PRODUCT_STORAGE_FILE_FIELDS,
            businessStorageFileService.getOperator(null)
        );
    }
    return rows;
}
```

核心原则：业务数据和文件绑定状态要放在同一个事务里处理。

### 20.2 ServiceImpl

```java
package com.ruoyi.system.service.impl;

import java.util.Arrays;
import java.util.List;
import jakarta.annotation.Resource;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import com.ruoyi.common.exception.BizException;
import com.ruoyi.common.utils.DateUtils;
import com.ruoyi.system.convert.ProductConvert;
import com.ruoyi.system.domain.Product;
import com.ruoyi.system.dto.ProductEditDto;
import com.ruoyi.system.dto.ProductQueryDto;
import com.ruoyi.system.dto.ProductSaveDto;
import com.ruoyi.system.mapper.ProductMapper;
import com.ruoyi.system.service.BusinessStorageFileField;
import com.ruoyi.system.service.IBusinessStorageFileService;
import com.ruoyi.system.service.IProductService;
import com.ruoyi.system.vo.ProductVo;

@Service
public class ProductServiceImpl implements IProductService {

    /**
     * Entity 文件字段映射，用于新增绑定、修改同步、删除标记。
     *
     * 第一个参数 bizType 建议保持稳定，不要随便改；它会写入文件记录，用于后续按业务归属管理文件。
     * Entity 阶段不需要回填文件列表，所以第三个参数传 null。
     */
    private static final List<BusinessStorageFileField<Product>> PRODUCT_STORAGE_FILE_FIELDS = Arrays.asList(
            BusinessStorageFileField.of("system:product:cover", Product::getCoverFileId, null),
            BusinessStorageFileField.of("system:product:attachment", Product::getAttachmentFileIds, null));

    /**
     * VO 文件字段映射，用于详情和列表回显。
     *
     * 第三个参数是 VO 的文件列表 setter，前端组件依赖这个列表展示预览图、原文件名和访问地址。
     */
    private static final List<BusinessStorageFileField<ProductVo>> PRODUCT_VO_STORAGE_FILE_FIELDS = Arrays.asList(
            BusinessStorageFileField.of("system:product:cover", ProductVo::getCoverFileId,
                    ProductVo::setCoverFileIdFileList),
            BusinessStorageFileField.of("system:product:attachment", ProductVo::getAttachmentFileIds,
                    ProductVo::setAttachmentFileIdsFileList));

    @Resource
    private ProductMapper productMapper;

    @Resource
    private ProductConvert productConvert;

    @Resource
    private IBusinessStorageFileService businessStorageFileService;

    @Override
    public ProductVo selectProductById(Long productId) {
        Product product = productMapper.selectProductById(productId);
        if (product == null) {
            throw new BizException("商品不存在");
        }
        ProductVo vo = productConvert.toVo(product);
        businessStorageFileService.fillStorageFileList(vo, PRODUCT_VO_STORAGE_FILE_FIELDS);
        return vo;
    }

    @Override
    public List<ProductVo> selectProductList(ProductQueryDto queryDto) {
        List<Product> products = productMapper.selectProductList(queryDto);
        List<ProductVo> list = productConvert.toVoList(products);
        businessStorageFileService.fillStorageFileList(list, PRODUCT_VO_STORAGE_FILE_FIELDS);
        return list;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public int insertProduct(ProductSaveDto saveDto) {
        Product product = productConvert.toEntity(saveDto);
        product.setCreateTime(DateUtils.getNowDate());
        int rows = productMapper.insertProduct(product);
        if (rows > 0) {
            businessStorageFileService.bindStorageFiles(product, String.valueOf(product.getProductId()),
                    PRODUCT_STORAGE_FILE_FIELDS, businessStorageFileService.getOperator(product));
        }
        return rows;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public int updateProduct(ProductEditDto editDto) {
        Product oldProduct = productMapper.selectProductById(editDto.getProductId());
        if (oldProduct == null) {
            throw new BizException("商品不存在");
        }

        Product product = productConvert.toEntity(editDto);
        product.setUpdateTime(DateUtils.getNowDate());
        int rows = productMapper.updateProduct(product);
        if (rows > 0) {
            businessStorageFileService.syncStorageFiles(product, oldProduct, String.valueOf(product.getProductId()),
                    PRODUCT_STORAGE_FILE_FIELDS, businessStorageFileService.getOperator(product));
        }
        return rows;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public int deleteProductByIds(Long[] productIds) {
        int rows = productMapper.deleteProductByIds(productIds);
        if (rows > 0) {
            businessStorageFileService.markStorageFilesWaitDeleteByBiz(productIds, PRODUCT_STORAGE_FILE_FIELDS,
                    businessStorageFileService.getOperator(null));
        }
        return rows;
    }
}
```

### 20.3 这个 Impl 做了什么

这份 Impl 里最关键的不是 CRUD 本身，而是文件处理的四个点：

- 查询详情：`fillStorageFileList(vo, fields)`，让上传组件能回显。
- 查询列表：`fillStorageFileList(list, fields)`，批量回填文件展示信息。
- 新增成功：`bindStorageFiles(entity, bizId, fields, operator)`，把临时文件绑定到业务数据。
- 修改成功：`syncStorageFiles(newEntity, oldEntity, bizId, fields, operator)`，同步新增文件和被移除文件。
- 删除成功：`markStorageFilesWaitDeleteByBiz(ids, fields, operator)`，把业务下文件标记为待删除。

注意事务边界：新增、修改、删除文件状态和业务数据必须在同一个事务中处理，否则可能出现“业务保存失败但文件已绑定”或“业务删除成功但文件仍然占用”的问题。

### 20.4 生成器文件字段 ServiceImpl 示例

如果某张业务表有多个文件字段，生成器应该生成两组文件字段映射：

- `STORAGE_FILE_FIELDS`：Entity 文件字段映射，用于新增、修改、删除时处理文件生命周期。
- `VO_STORAGE_FILE_FIELDS`：VO 文件回显字段映射，用于详情和列表查询时填充 `xxxList`。

下面用点位管理的写法作为模板示例。假设业务表里有 `file1`、`file2`、`file4`、`file5` 四个文件字段，其中这些字段在代码生成页面选择了图片上传或文件上传组件：

```java
/**
 * 文件字段生命周期映射。
 * <p>
 * 代码生成页面选择图片上传或文件上传的字段会进入该列表，业务表字段保存 fileId/fileIds。
 */
private static final List<BusinessStorageFileField<Node>> STORAGE_FILE_FIELDS = Arrays.asList(
        BusinessStorageFileField.of("system:node:file1", Node::getFile1, null),
        BusinessStorageFileField.of("system:node:file2", Node::getFile2, null),
        BusinessStorageFileField.of("system:node:file4", Node::getFile4, null),
        BusinessStorageFileField.of("system:node:file5", Node::getFile5, null));

/**
 * VO 文件回显字段映射。
 * <p>
 * 只有列表显示=true 且选择上传组件的字段才会生成 xxxList 回显字段。
 */
private static final List<BusinessStorageFileField<NodeVo>> VO_STORAGE_FILE_FIELDS = Arrays.asList(
        BusinessStorageFileField.of("system:node:file1", NodeVo::getFile1, NodeVo::setFile1List),
        BusinessStorageFileField.of("system:node:file2", NodeVo::getFile2, NodeVo::setFile2List),
        BusinessStorageFileField.of("system:node:file4", NodeVo::getFile4, NodeVo::setFile4List),
        BusinessStorageFileField.of("system:node:file5", NodeVo::getFile5, NodeVo::setFile5List));
```

这里的 `bizType` 建议按下面格式生成：

```text
模块名:业务名:字段名
```

示例：

```text
system:node:file1
system:node:file2
```

`STORAGE_FILE_FIELDS` 的第三个参数传 `null`，因为 Entity 不需要回填文件列表；`VO_STORAGE_FILE_FIELDS` 的第三个参数传 `NodeVo::setFile1List` 这类 setter，因为 VO 要把文件展示列表返回给前端。

#### 查询详情回显

```java
@Override
public NodeVo selectNodeById(Long id)
{
    NodeVo nodeVo = NodeConvert.INSTANCE.toVo(nodeMapper.selectNodeById(id));
    businessStorageFileService.fillStorageFileList(nodeVo, VO_STORAGE_FILE_FIELDS);
    return nodeVo;
}
```

查询详情时必须调用：

```java
businessStorageFileService.fillStorageFileList(nodeVo, VO_STORAGE_FILE_FIELDS);
```

否则前端编辑弹窗只能拿到 `file1` 这种 fileId 字符串，拿不到 `file1List`，上传组件就无法回显原文件名、预览图和访问地址。

#### 查询列表回显

```java
@Override
public List<NodeVo> selectNodeList(NodeQueryDto node)
{
    List<NodeVo> list = NodeConvert.INSTANCE.toVoList(
            nodeMapper.selectNodeList(NodeConvert.INSTANCE.toEntity(node)));
    businessStorageFileService.fillStorageFileList(list, VO_STORAGE_FILE_FIELDS);
    return list;
}
```

列表回显时调用集合重载方法：

```java
businessStorageFileService.fillStorageFileList(list, VO_STORAGE_FILE_FIELDS);
```

这会批量收集当前页所有文件 ID，再统一查询文件记录并回填，避免在循环里逐条查询文件。

#### 新增时绑定文件

```java
@Transactional(rollbackFor = Exception.class)
@Override
public int insertNode(NodeSaveDto node)
{
    Node entity = NodeConvert.INSTANCE.toEntity(node);
    entity.setCreateTime(DateUtils.getNowDate());
    int rows = nodeMapper.insertNode(entity);
    if (rows > 0)
    {
        // 新增成功后用数据库生成的主键作为 bizId，把临时文件绑定到当前业务数据。
        businessStorageFileService.bindStorageFiles(entity, String.valueOf(entity.getId()),
                STORAGE_FILE_FIELDS, businessStorageFileService.getOperator(entity));
    }
    return rows;
}
```

新增时一定要在 `insert` 成功后绑定文件，因为只有数据库插入成功后才能拿到业务主键 `bizId`。

#### 修改时同步文件

```java
@Transactional(rollbackFor = Exception.class)
@Override
public int updateNode(NodeEditDto node)
{
    Node entity = NodeConvert.INSTANCE.toEntity(node);
    Node oldEntity = nodeMapper.selectNodeById(entity.getId());
    entity.setUpdateTime(DateUtils.getNowDate());
    int rows = nodeMapper.updateNode(entity);
    if (rows > 0 && oldEntity != null)
    {
        // 修改成功后同步新旧 fileId 集合，表单移除的文件会被标记为待删除。
        businessStorageFileService.syncStorageFiles(entity, oldEntity, String.valueOf(entity.getId()),
                STORAGE_FILE_FIELDS, businessStorageFileService.getOperator(entity));
    }
    return rows;
}
```

修改时必须先查旧实体，因为 `syncStorageFiles` 要比较“旧 fileId 集合”和“新 fileId 集合”：

- 新增的 fileId：绑定到当前业务。
- 保留的 fileId：不重复处理。
- 移除的 fileId：标记为待删除。

#### 删除时标记待删除

```java
@Transactional(rollbackFor = Exception.class)
@Override
public int deleteNodeByIds(Long[] ids)
{
    int rows = nodeMapper.deleteNodeByIds(ids);
    if (rows > 0)
    {
        // 删除业务数据后，按 bizId 和 bizType 统一把业务文件标记为待删除。
        businessStorageFileService.markStorageFilesWaitDeleteByBiz(ids, STORAGE_FILE_FIELDS,
                businessStorageFileService.getOperator(null));
    }
    return rows;
}
```

删除时不需要先查出所有文件字段值，因为文件记录里已经保存了 `bizType` 和 `bizId`，可以按业务 ID 批量标记。

## 21. 文件体系详细说明

### 21.1 文件上传到业务绑定的完整流程

```text
1. 前端选择文件
2. 上传组件调用通用上传接口，并传 uploadScene
3. 后端按 uploadScene 校验大小、扩展名、访问级别、存储平台
4. 文件写入本地、MinIO、OSS 或 COS
5. sys_storage_file 写入文件记录，此时还没有业务归属或仍是临时状态
6. 前端拿到 fileId，把 fileId 放进业务表单字段
7. 用户点击保存业务表单
8. 业务表保存成功，拿到业务主键 bizId
9. ServiceImpl 调用 bindStorageFiles 绑定 fileId、bizType、bizId
10. 查询详情或列表时，ServiceImpl 调用 fillStorageFileList 回填文件展示信息
```

### 21.2 为什么业务表只存 fileId

不建议业务表直接保存 URL：

```text
https://bucket.example.com/upload/public/image/2026/10/10/a.png
```

推荐保存：

```text
1800000000000000001
```

多个附件用逗号分隔：

```text
1800000000000000001,1800000000000000002
```

原因：

- URL 可能会变，fileId 不应该变。
- 存储平台可能从本地切到 MinIO、OSS、COS。
- 公开文件、私有文件、临时授权文件的访问地址生成规则不同。
- 私有文件不能把真实存储地址直接给前端。
- 文件清理、绑定、待删除都依赖文件记录。

### 21.3 uploadScene 和 bizType 的区别

| 名称 | 谁传入 | 什么时候用 | 示例 | 作用 |
| --- | --- | --- | --- | --- |
| `uploadScene` | 前端上传组件 | 上传文件时 | `commonImg`、`commonFile` | 控制大小、扩展名、访问级别、路径前缀 |
| `bizType` | 后端 ServiceImpl | 文件绑定业务时 | `system:product:cover` | 标识文件属于哪类业务字段 |

一个 `uploadScene` 可以服务多个业务字段。例如商品封面、文章封面都可以用 `commonImg` 上传，但绑定时应该使用不同的 `bizType`：

```java
BusinessStorageFileField.of("system:product:cover", Product::getCoverFileId, null)
BusinessStorageFileField.of("cms:article:cover", Article::getCoverFileId, null)
```

### 21.8 修改文件时发生什么

假设旧数据：

```text
attachmentFileIds = 1,2,3
```

用户编辑后提交：

```text
attachmentFileIds = 2,3,4
```

`syncStorageFiles` 会做集合差异：

| 文件 ID | 状态 |
| --- | --- |
| `1` | 被移除，标记待删除 |
| `2` | 保留，不处理 |
| `3` | 保留，不处理 |
| `4` | 新增，绑定到当前业务 |

这就是修改时必须先查旧数据的原因。

### 21.9 删除业务时为什么不立刻物理删除文件

删除业务数据时调用：

```java
businessStorageFileService.markStorageFilesWaitDeleteByBiz(productIds, PRODUCT_STORAGE_FILE_FIELDS,
        businessStorageFileService.getOperator(null));
```

它只把文件标记为待删除，不直接删除真实文件。这样做有几个好处：

- 业务误删后还有恢复窗口。
- 避免事务未提交时就删除真实文件。
- 对象存储删除失败时可以重试。
- 可以通过定时任务集中清理，减少业务请求耗时。

### 21.10 常见文件问题排查

| 问题 | 优先检查 |
| --- | --- |
| 上传失败 | `uploadScene` 是否存在，扩展名和大小是否符合配置 |
| 保存成功但文件未绑定 | ServiceImpl 是否调用 `bindStorageFiles`，bizId 是否为数据库主键 |
| 修改后旧文件没释放 | 是否先查询旧实体，并调用 `syncStorageFiles` |
| 删除业务后文件仍占用 | 是否调用 `markStorageFilesWaitDeleteByBiz` |
| 图片不回显 | 详情或列表是否调用 `fillStorageFileList`，VO 是否有 `xxxFileList` |
| 附件名不显示 | 文件记录是否有 `originalFilename`，前端是否读取文件列表 |
| 私有文件打不开 | 临时访问地址是否过期，当前用户是否有业务数据权限 |

### 21.11 ImageUpload 组件参数

图片上传组件用于头像、封面、图片集等字段。业务页面常用写法：

```vue
<image-upload
  v-model="form.file1"
  v-model:storage-file-list="form.file1List"
  value-type="fileId"
  upload-scene="commonImg"
  :limit="3"
  :file-size="5"
  :file-type="['png', 'jpg', 'jpeg']"
  :is-show-tip="true"
/>
```

参数说明：

| 参数 | 类型 | 默认值 | 是否建议生成到业务代码 | 说明 |
| --- | --- | --- | --- | --- |
| `modelValue` / `v-model` | `String / Number / Array` | 无 | 必须 | 业务字段值。`value-type="fileId"` 时保存 fileId 或逗号分隔 fileIds |
| `storageFileList` / `v-model:storage-file-list` | `Array` | `[]` | 文件字段建议生成 | 后端返回的文件回显列表，用于编辑回显、预览图、文件名 |
| `value-type` | `String` | 组件默认值 | 文件字段必须生成 | 建议固定传 `fileId`，表示提交 fileId，不提交 URL |
| `upload-scene` | `String` | `commonImg` 或组件默认值 | 建议生成 | 上传场景，后端按场景控制大小、扩展名、访问权限 |
| `platform` | `String` | `undefined` | 按需生成 | 指定存储平台；一般不写，由后端默认平台决定 |
| `limit` | `Number` | 组件默认值 | 按代码生成配置生成 | 最大上传数量 |
| `file-size` | `Number` | 组件默认值 | 按代码生成配置生成 | 前端提示或校验的单文件大小，单位通常为 MB |
| `file-type` | `Array` | 图片类型默认值 | 按代码生成配置生成 | 允许上传的图片扩展名 |
| `is-show-tip` | `Boolean` | `true` | 通常不用生成 | 是否显示上传提示 |

代码生成建议：

- 普通业务不需要把所有默认参数都生成出来。
- 只有业务页面配置了特殊限制时，才生成 `limit`、`file-size`、`file-type`。
- `value-type="fileId"`、`upload-scene`、`v-model:storage-file-list` 对文件生命周期很关键，建议文件字段统一生成。

### 21.12 FileUpload 组件参数

附件上传组件用于合同、资料、压缩包、文档等字段。业务页面常用写法：

```vue
<file-upload
  v-model="form.file2"
  v-model:storage-file-list="form.file2List"
  value-type="fileId"
  upload-scene="commonFile"
  :limit="5"
  :file-size="10"
  :file-type="['pdf', 'doc', 'docx', 'xls', 'xlsx']"
  :is-show-tip="true"
/>
```

参数说明：

| 参数 | 类型 | 默认值 | 是否建议生成到业务代码 | 说明 |
| --- | --- | --- | --- | --- |
| `modelValue` / `v-model` | `String / Number / Array` | 无 | 必须 | 业务字段值。单文件可保存一个 fileId，多文件可保存逗号分隔 fileIds |
| `storageFileList` / `v-model:storage-file-list` | `Array` | `[]` | 文件字段建议生成 | 附件回显列表，展示原文件名和下载地址 |
| `value-type` | `String` | 组件默认值 | 文件字段必须生成 | 建议固定传 `fileId` |
| `upload-scene` | `String` | `commonFile` 或组件默认值 | 建议生成 | 上传场景，通常附件用 `commonFile` |
| `platform` | `String` | `undefined` | 按需生成 | 指定上传平台；多租户或特殊业务才需要 |
| `limit` | `Number` | `5` | 按代码生成配置生成 | 最大上传数量 |
| `file-size` | `Number` | `5` | 按代码生成配置生成 | 单文件大小限制，单位通常为 MB |
| `file-type` | `Array` | `['doc', 'xls', 'ppt', 'txt', 'pdf']` | 按代码生成配置生成 | 允许上传的附件扩展名 |
| `is-show-tip` | `Boolean` | `true` | 通常不用生成 | 是否显示上传提示 |

如果业务页面传了 `:file-type`，它表示替换组件默认类型，而不是在默认类型上追加。比如：

```vue
<file-upload :file-type="['pdf']" />
```

表示该业务只允许上传 PDF。

如果希望在默认类型基础上增加扩展名，需要显式写全：

```vue
<file-upload :file-type="['doc', 'xls', 'ppt', 'txt', 'pdf', 'zip']" />
```

### 21.13 文件组件参数什么时候生成

代码生成器建议按下面规则生成前端组件参数：

| 参数 | 生成规则 |
| --- | --- |
| `v-model` | 必须生成，绑定业务字段 |
| `v-model:storage-file-list` | 文件上传、图片上传字段必须生成，绑定 `xxxList` |
| `value-type="fileId"` | 文件上传、图片上传字段必须生成 |
| `upload-scene` | 建议生成，图片默认 `commonImg`，附件默认 `commonFile` |
| `platform` | 默认不生成，除非代码生成页面提供了平台选择 |
| `limit` | 和默认值不同或代码生成页面配置了数量时生成 |
| `file-size` | 和默认值不同或代码生成页面配置了大小时生成 |
| `file-type` | 和默认值不同或代码生成页面配置了类型时生成 |
| `is-show-tip` | 默认不生成，只有业务明确关闭提示时生成 `:is-show-tip="false"` |

这样生成出来的页面不会塞满无意义默认参数，同时关键的 fileId、回显列表、上传场景不会漏。

```java
package com.ruoyi.system.service.impl;

import java.util.Arrays;
import java.util.List;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import com.ruoyi.common.exception.BizException;
import com.ruoyi.common.utils.DateUtils;
import com.ruoyi.system.convert.ProductConvert;
import com.ruoyi.system.domain.Product;
import com.ruoyi.system.dto.ProductEditDto;
import com.ruoyi.system.dto.ProductQueryDto;
import com.ruoyi.system.dto.ProductSaveDto;
import com.ruoyi.system.mapper.ProductMapper;
import com.ruoyi.system.service.BusinessStorageFileField;
import com.ruoyi.system.service.IBusinessStorageFileService;
import com.ruoyi.system.service.IProductService;
import com.ruoyi.system.vo.ProductVo;

@Service
public class ProductServiceImpl implements IProductService {

    private static final List<BusinessStorageFileField<Product>> STORAGE_FILE_FIELDS = Arrays.asList(
            BusinessStorageFileField.of("system:product:coverFileId", Product::getCoverFileId, null),
            BusinessStorageFileField.of("system:product:attachmentFileIds", Product::getAttachmentFileIds, null));

    private static final List<BusinessStorageFileField<ProductVo>> VO_STORAGE_FILE_FIELDS = Arrays.asList(
            BusinessStorageFileField.of("system:product:coverFileId", ProductVo::getCoverFileId,
                    ProductVo::setCoverFileIdList),
            BusinessStorageFileField.of("system:product:attachmentFileIds", ProductVo::getAttachmentFileIds,
                    ProductVo::setAttachmentFileIdsList));

    @Autowired
    private ProductMapper productMapper;

    @Autowired
    private IBusinessStorageFileService businessStorageFileService;

    @Override
    public ProductVo selectProductById(Long productId) {
        Product product = productMapper.selectProductById(productId);
        if (product == null) {
            throw new BizException("商品不存在");
        }
        ProductVo vo = ProductConvert.INSTANCE.toVo(product);
        businessStorageFileService.fillStorageFileList(vo, VO_STORAGE_FILE_FIELDS);
        return vo;
    }

    @Override
    public List<ProductVo> selectProductList(ProductQueryDto queryDto) {
        List<ProductVo> list = ProductConvert.INSTANCE.toVoList(
                productMapper.selectProductList(ProductConvert.INSTANCE.toEntity(queryDto)));
        businessStorageFileService.fillStorageFileList(list, VO_STORAGE_FILE_FIELDS);
        return list;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public int insertProduct(ProductSaveDto saveDto) {
        Product entity = ProductConvert.INSTANCE.toEntity(saveDto);
        entity.setCreateTime(DateUtils.getNowDate());
        int rows = productMapper.insertProduct(entity);
        if (rows > 0) {
            businessStorageFileService.bindStorageFiles(entity, String.valueOf(entity.getProductId()),
                    STORAGE_FILE_FIELDS, businessStorageFileService.getOperator(entity));
        }
        return rows;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public int updateProduct(ProductEditDto editDto) {
        Product entity = ProductConvert.INSTANCE.toEntity(editDto);
        Product oldEntity = productMapper.selectProductById(entity.getProductId());
        if (oldEntity == null) {
            throw new BizException("商品不存在");
        }
        entity.setUpdateTime(DateUtils.getNowDate());
        int rows = productMapper.updateProduct(entity);
        if (rows > 0) {
            businessStorageFileService.syncStorageFiles(entity, oldEntity, String.valueOf(entity.getProductId()),
                    STORAGE_FILE_FIELDS, businessStorageFileService.getOperator(entity));
        }
        return rows;
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public int deleteProductByIds(Long[] productIds) {
        int rows = productMapper.deleteProductByIds(productIds);
        if (rows > 0) {
            businessStorageFileService.markStorageFilesWaitDeleteByBiz(productIds, STORAGE_FILE_FIELDS,
                    businessStorageFileService.getOperator(null));
        }
        return rows;
    }
}
```

## 23. 新业务落地检查清单

每做完一个业务模块，按这个清单过一遍：

- Controller 列表返回 `TableDataInfo`。
- Controller 非分页接口返回 `Response<T>` 或 `Response<Void>`。
- 新增、修改、删除 Service 返回 `int`。
- SaveDTO、EditDTO 有必要的校验注解。
- QueryDTO 只放查询条件。
- VO 只放前端需要展示的数据。
- Convert 覆盖 DTO、Entity、VO 转换。
- Mapper XML 有逻辑删除条件。
- 新增、修改、删除加了 `@Log`。
- 文件字段保存 fileId，不保存 URL。
- 文件字段 VO 返回对应 `xxxFileList`。
- 文件字段新增、修改、删除同步生命周期。
- 前端 API 路径、权限标识、菜单权限一致。
- 前端弹窗新增、编辑、回显正常。
- 表格图片、附件展示正常。
- 导出、导入按业务需要测试。
- 异常时后台异常日志能看到记录。
