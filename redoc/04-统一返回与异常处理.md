# 统一返回类改造说明

## 改造边界

本次改造采用增量方案，不替换若依原有返回体系。

- 若依原生 `AjaxResult`、`R`、`TableDataInfo` 保持原样
- 分页列表接口继续返回 `TableDataInfo`
- 新增业务的非分页接口统一返回 `Response<T>`
- 新增、修改、删除接口返回 `Response<Void>`
- 全局异常处理统一返回 `Response<Void>`

这样既保留若依存量代码和分页组件的默认行为，又让后续新增接口具备统一响应结构。

## Response 结构

`Response<T>` 保持业务响应语义，不额外加入若依的 `code/msg` 字段。

```json
{
  "success": true,
  "message": "操作成功",
  "errorCode": null,
  "data": {}
}
```

失败响应示例：

```json
{
  "success": false,
  "message": "点位不存在",
  "errorCode": "NODE_NOT_FOUND",
  "data": null
}
```

## 分页接口

分页接口继续采用若依原始结构：

```json
{
  "total": 100,
  "rows": [],
  "code": 200,
  "msg": "查询成功"
}
```

Controller 保持若依写法：

```java
@GetMapping("/list")
public TableDataInfo list(QueryDTO query)
{
    startPage();
    List<VO> list = service.selectList(query);
    return getDataTable(list);
}
```

前端分页页面继续读取 `rows/total`，无需改成 `data.records`。

## 非分页接口

详情查询返回明确的数据类型：

```java
@GetMapping("/{id}")
public Response<EntityVO> getInfo(@PathVariable Long id)
{
    return Response.success(service.selectById(id));
}
```

新增、修改、删除只表达成功失败：

```java
@PostMapping
public Response<Void> add(@RequestBody SaveDTO dto)
{
    return Response.toResponse(service.insert(dto));
}
```

MyBatis-Plus 直接返回 `boolean` 的场景，也使用同一个转换入口：

```java
@PostMapping
public Response<Void> add(@RequestBody SaveDTO dto)
{
    return Response.toResponse(service.save(dto));
}
```

## 代码生成器

生成器模板按以下规则生成：

- 普通分页 `list` 方法继续生成 `TableDataInfo`
- 树表 `list` 方法生成 `Response<List<Entity>>`
- 详情接口生成 `Response<Entity>`
- 新增、修改、删除生成 `Response<Void>`
- Service 和 Mapper 的新增、修改、删除默认返回 `int` 影响行数
- Controller 使用 `Response.toResponse(rows)` 转换影响行数
- 导出接口继续直接写 `HttpServletResponse`
- TypeScript 分页 API 返回 `TableDataInfo<T>`
- TypeScript 非分页 API 返回 `Response<T>` 或 `Response<void>`
- TypeScript 公共类型生成到 `vue/types/api/common.ts`

## 全局异常

新增业务异常 `BizException` 后，全局异常处理器返回 `Response<Void>`：

```java
@ExceptionHandler(BizException.class)
public Response<Void> handleBizException(BizException e, HttpServletRequest request)
{
    return Response.fail(e);
}
```

若依已有的通用异常处理也可以返回 `Response<Void>`。前端拦截器识别到 `success` 字段后，会按 `success/message/errorCode` 转换为原有前端判断需要的 `code/msg`，因此不需要污染 `Response` 本身。

## 前端兼容

`src/utils/request.js` 保持兼容逻辑：

- 原若依响应包含 `code/msg/rows/total` 时，按原逻辑处理
- 新响应包含 `success/message/errorCode/data` 时，映射成前端已有成功或失败流程
- 分页页面仍读取 `rows/total`
- 新增业务详情、保存、删除等接口可以直接使用 `Response<T>`
